# 扭蛋打卡 GachaHabit · 需求与设计文档

> 版本 v0.1 · 2026-09-20 · 状态：**待确认**
> 配套原型：`prototype/index.html`（双击即可在浏览器打开体验）

---

## 1. 项目概述

一款用「**随机积分 + 扭蛋抽奖**」制造多巴胺、帮助自我管理的习惯打卡应用。

- **形态**：响应式网页（手机 / 电脑均衡），纯前端 + 浏览器本地存储，可部署到 GitHub Pages 免费托管
- **核心循环**：自己制定项目 → 每日打卡摇分（扭蛋动画）→ 强制项目未完成则日结摇负分 → 热力图 / 周月年报表回顾 → 成就激励（规划中）
- **设计基调**：深色「夜间游戏厅」风格，金色 = 收获，红色 = 失血；一切数值变化都要有动画和仪式感

## 2. 核心玩法规则

### 2.1 项目（习惯）

| 字段 | 说明 |
|---|---|
| 名称 + emoji | 如「🌙 早睡」 |
| 标签 | 自建标签，一个项目可挂多个标签（如 健康 / 学习 / 运动） |
| 正分区间 `[min, max]` | 打卡成功时扭蛋摇出的分数范围，整数；`min = max` 即固定分 |
| 强制打卡开关 | 开启后才有负分机制；非强制项目不打卡**无任何惩罚** |
| 负分区间 `[min, max]` | 仅强制项目需要，如 50 ~ 200 表示扣 50~200 分；**打开强制开关时默认与正分区间一致，可再修改** |
| 状态 | 使用中 / 归档（归档不再出现在今日列表，历史保留） |

- 负分区间**允许从 0 开始**：0 意味着有概率摇出免罚 → 日结也有悬念（**待确认**）
- 所有分数均为整数

### 2.2 每日流程

1. 每个项目**每天最多打卡一次**，打卡 → 扭蛋动画 → 摇出正分入账
2. **打卡后当天锁定，不可重摇**（防止反复摇到满意为止，保证积分含金量）（**待确认**）
3. 非强制项目：想打就打，不打没惩罚
4. 强制项目当天未打卡时，有三种走向：
   - 什么都不做 → 等日结时系统自动摇负分
   - 点「**认输**」→ 提前摇出负分（主动止损，同样有扭蛋动画）
   - 点「**休息**」→ 今日免罚（休息日不断连续天数）

### 2.3 日结（自动结算）

- 纯前端无法保证半夜 0 点在运行，实际规则：
  - app 开着跨过 0 点 → 实时结算并弹出「结算单」
  - 否则**下次打开时静默补结算**（可能攒了多天），同样以结算单告知明细
- 结算对象：当天已存在且使用中的强制项目里，既没打卡也没休息的
- 负分**静默扣分**（无动画、不打断），扭蛋动画只留给「打卡」和「认输」（✅ 已确认）
- 结算产生的分数**追溯到对应日期**，热力图与报表按记录日期统计

### 2.4 分数与总分

- 当日总分 = 当天所有记录之和（首页大数字展示）
- 历史记录不可修改、不可删除（归档项目的历史仍计入统计）
- 所有日期按设备本地时区的自然日计算

## 4. 界面设计

### 4.1 信息架构

底部 Tab 导航（移动优先，桌面同构居中 960px）：**今日 / 统计 / 项目**

- **今日页**：顶部 hero 卡片（日期 + 今日总分大数字 + 进度/连续天数）→ 标签筛选行 → 项目卡片网格
  - 卡片状态机：`未打卡`（打卡/休息/认输按钮）→ `已打卡 +N` / `已认输 -N` / `休息中`（均锁定）
- **统计页**：周期切换（本周/本月/本年，‹› 翻上一期）→ KPI 行（总分/日均、强制完成率、打卡次数、最佳单日）→ 每日/每月总分趋势 → 标签得分分布 → 项目得分排行 → 月/年双视图热力图 → 可展开的数据表
- **项目页**：项目列表（编辑 / 删除）+ 新建表单（emoji 选择、标签多选、双区间、强制开关）+ 数据导入导出 / 重置

### 4.2 图表规范（已用色板验证器校验）

深色卡片底色 `#161c33` 上验证通过：

| 用途 | 色值 | 说明 |
|---|---|---|
| 热力图·正分 3 档 | `#166534 → #22c55e → #86efac` | 单色渐变臂，越亮=赚越多 |
| 热力图·负分 3 档 | `#9f1239 → #e11d48 → #fb7185` | 红色臂，越亮=亏越多 |
| 热力图·无记录 | `#232b4a` + 细描边 | 中性灰蓝 |
| 标签分类色（8 色） | `#3987e5, #d95926, #199e70, #c98500, #d55181, #008300, #9085e9, #e66767` | 固定顺序分配给标签，永不错开复用 |
| 分数正/负（文字与 Chip） | 绿 `#4ade80` / 红 `#fb7185` | 附符号 +/−，不裸靠颜色 |

- 趋势图为**绕零基线的双向柱状图**（赚向上绿、亏向下红）
- 柱宽 ≤24px、数据端 4px 圆角、基线端直角；网格线 1px 实线弱化
- 大数字用比例数字（proportional），仅表格/坐标轴用 tabular-nums
- 每个图表都有 hover/focus 提示，且提供数据表视图（tooltip 永不作为唯一读数途径）
- 今日总分为全页唯一 hero figure（≥48px）

### 4.3 扭蛋动画分镜（核心爽点）

| 阶段 | 时长 | 画面 |
|---|---|---|
| 1 入场 | 250ms | 遮罩弹出，扭蛋胶囊落下就位 |
| 2 悬念摇晃 | 1.5~2.1s（随机） | 背景金色射线旋转，摇晃幅度渐强 |
| 3 爆开 | 300ms | 上盖飞出旋转、白光一闪 |
| 4 揭晓 | 900ms | 数字从 0 滚动到结果，粒子迸发；分数 ≥ 区间 85% 触发「大奖」加量彩带 |
| 5 收下 | — | 按钮「收下」→ 数字飞入当日总分，总分滚动上涨 |

- **大奖评级文案**：正分按区间百分位 → 「🎯满分抽出!! / ✨欧皇附体!! / 🎉欧气满满! / 👍不错不错」；负分 → 「💔心态崩了… / 😱大失血! / 😅止血成功」
- **负分差异**：胶囊换灰色涂装、无金射线、无彩带、屏幕短促震动、数字红色——惩罚也要有仪式感
- **动画适用范围（✅ 已确认）**：扭蛋动画只用于「打卡」与「认输」；常规日结静默扣分，以结算单通知
- **分级音效（✅ v0.2 新增）**：Web Audio 现场合成、无音频文件；摇晃期棘轮咔哒加速渐升调，揭晓按分数分级——小分双音 / 中分三连音 / 大分四音琶音 / 满分或 ≥85% 触发五音琶音+和弦+闪光噪声；0 分闷音；负分低沉下落音分三档递增沉重；收下有轻快双击；顶栏 🔊/🔇 一键静音
- 音效暂不做（浏览器自动播放限制 + 骚扰权衡），预留后续开关

## 5. 数据模型

```ts
interface Tag      { id: string; name: string; color: string }
interface Project  {
  id: string; name: string; emoji: string; tagIds: string[];
  posMin: number; posMax: number          // 打卡成功区间
  mandatory: boolean
  negMin?: number; negMax?: number        // 仅强制项目
  archived: boolean; archivedAt?: string; createdAt: string  // 日期均为 YYYY-MM-DD
}
interface Checkin  { score: number; status: 'done'|'failed'|'rest'; via?: 'user'|'auto'; ts: number }
// 存储：checkins: Record<`${projectId}|${date}`, Checkin>
// 成就：achievements: Record<string, {unlockedAt: string}>（预留）
```

存储位置 `localStorage`；导出 / 导入为完整 JSON 快照；未来接后端时增加 `accountId` 即可。

## 6. 技术方案

- **栈**：React 18 + TypeScript + Vite；状态 zustand（persist 直连 localStorage）；样式手写 CSS（沿用原型的设计变量，视觉与原型 1:1）；图表自绘 SVG（沿用原型实现，已过色板校验）；扭蛋动画 CSS keyframes + DOM 粒子
- **结构**：`src/views/{Today,Stats,Projects}` + `src/components/{GachaModal,Heatmap,…}` + `src/lib/{date,rng,logic}`
- **部署**：GitHub Actions 推 main 自动构建发布到 GitHub Pages（纯静态，base `./`）
- **选型理由**：本地优先零成本；数据量小（每天几十条 JSON）；成就/后端都是增量模块，不动地基
